# ZInitiatives maintenance rules

ZInitiatives is the shared GitHub Registry, not an Initiative content repository. Keep manifest inputs under `registry/`, generated projections under `generated/`, protocol schemas under `schemas/`, and protocol documentation under `docs/prds/`.

The hierarchy is exactly `Initiative → Spec → Plan`. Manifest paths point to files in the Initiative repository and never contain local absolute paths or credentials. Generated files are derived from manifests and must be regenerated by the compiler when that implementation exists.

Read [Initiative Registry Protocol](docs/prds/initiative-registry-protocol.md) before changing schemas, manifest fields, generated outputs, or path rules. Validate JSON syntax, schema constraints, cross-manifest references, and `git diff --check` before handoff.

## Human-led closeout

ZInitiatives is a global coordination index, not a durable-document repository. Keep only the navigation facts needed to coordinate parallel work across devices and Agents; keep temporary notes, execution detail, receipts, and durable content in the Initiative repository that owns them.

When a Plan reaches a terminal state, or a Spec is implemented, superseded, or no longer useful for current coordination, remind the Human to perform closeout before declaring the work complete:

1. Consolidate useful temporary material into the owning Initiative repository's durable documents.
2. Update the owning Spec or Plan source and its repository-relative Registry reference when navigation has changed.
3. Regenerate and validate Registry projections so every remaining link is current.
4. Leave completed or superseded entries in place when they still provide useful history or references; do not delete them automatically.

The current v1 schemas define `lifecycle` only for Initiative manifests. Until Spec and Plan lifecycle fields are added through a coordinated schema, validator, compiler, and protocol change, record execution completion in the owning Plan or Spec and keep the Registry manifest as a stable navigation entry. Do not invent unsupported manifest fields.

ZInitiatives does not run automatic compaction, TTL deletion, or history migration. A Human may remove obsolete navigation entries during a later closeout after checking references; Git history and the owning Initiative repository remain the source for historical detail.
